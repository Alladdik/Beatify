# Beatify на VPS — папка, яку кидаєш на сервер

Ця папка — «стартер». Ти копіюєш її на VPS один раз, запускаєш `install.sh`, а далі сервер **сам тягне нові версії з GitHub** (раз на 5 хвилин) і перезбирає сайт. Код і музика не змішуються: код приходить з GitHub, музика лишається у Docker-томі на сервері й на твоєму ПК.

## 1. Підготовка (один раз)

1. **Запуш усе на GitHub** (`git add -A && git commit && git push`) — сервер бере лише те, що є в репозиторії.
2. Репозиторій приватний, тому серверу потрібен токен лише для читання:
   GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Repository access: тільки `Beatify`, Permissions → **Contents: Read-only**.
3. Потрібен VPS з Ubuntu/Debian, від 2 ГБ RAM (перша збірка важка). Для HTTPS — домен з A-записом на IP сервера.

## 2. Встановлення

З Windows скопіюй папку на сервер:

```powershell
scp -r .\vps-deploy root@ТВІЙ_IP:/root/
```

На сервері:

```bash
ssh root@ТВІЙ_IP
cd /root/vps-deploy
sed -i 's/\r$//' *.sh                     # про всяк випадок, якщо файли з Windows
cp config.env.example config.env
nano config.env                           # встав GITHUB_TOKEN і (за бажанням) DOMAIN
bash install.sh
```

Скрипт поставить Docker і git, склонує код (поверхнево — історія репозиторію велика, тягнеться лише остання версія), згенерує секрети, збере й запустить сайт, увімкне автооновлення та щоденне оновлення `yt-dlp` (щоб не повторилась помилка 403).

> **Першим зареєструйся сам** — перший акаунт стає адміністратором. Якщо переносиш свою базу (п. 3), акаунт перенесеться разом з нею.

## 3. Перенести свою музику з ПК

Твої файли в `server\wwwroot\uploads` (≈780 МБ) і база (треки, плейлисти, акаунти) лежать локально. Скрипт тільки **читає** їх — на твоєму диску нічого не видаляється й не змінюється:

```powershell
.\vps-deploy\upload-media.ps1 -Server root@ТВІЙ_IP
```

- `-SkipDb` — лише файли, `-SkipFiles` — лише база.
- База на сервері **замінюється** дампом локальної — роби це один раз після встановлення, поки на сервері ніхто не зареєструвався.
- Файли додаються до тих, що вже є на сервері; повторний запуск безпечний.

## Як це працює далі

| Що | Як |
|---|---|
| Нова версія коду | `git push` → за ≤5 хв сервер підтягне й перезбере (лог: `/var/log/beatify-update.log`) |
| Оновити негайно | `bash /opt/beatify/vps-deploy/update-now.sh` |
| Вимкнути автооновлення | `AUTO_UPDATE_MINUTES=0` у `config.env` і `bash install.sh` ще раз |
| yt-dlp | оновлюється щодня о 04:17 і при кожній перезбірці |
| Логи сайту | `docker compose -f /opt/beatify/deploy/docker-compose.yml logs -f app` |
| Дані | томи Docker (`beatify_pgdata`, `beatify_uploads`) — переживають оновлення; бекапи див. `deploy/README.md` |

Під час перезбірки сайт ~1–3 хвилини недоступний. Секрети (`deploy/.env`) створюються на сервері й ніколи не потрапляють у git.
